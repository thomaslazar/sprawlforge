# Arterials Phase 2 (Shores) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Arterials and the highway turn along coasts and lakes instead of stopping at them (a seeded few arterials stay dock ends), the field gets a waterfront band with gaps, the highway no longer dead-ends at the sea or decks a river mouth, and a highway crossed square no longer blocks a river deck (investigation item 7b).

**Architecture:** All inside the tracer and the field, as in phase 1. `field.ts` gains a seeded shore profile that reshapes the boundary basis. `traceHalf` gains a shore steer: when water lies ahead that is not a river it may bridge, the raw direction becomes the shore tangent and the existing turn clamp makes it a curve. The highway uses the same steer through `HIGHWAY_OPTS` (200 m lookahead, its own clamp, no dock) plus a deck length cap. The river-deck clearance treats the highway by angle and crossing instead of distance.

**Tech Stack:** TypeScript, vitest, Playwright uicheck (`PORT=4174 tools/uicheck/run.sh`).

**Spec:** `docs/specs/2026-10-12-arterials-design.md` §5 (phase 2), constraints from §1, §3, §7, §8, §9. Phases 1 and 3 are out of scope.

### Task 1: shore profile and boundary basis

**Files:**
- Modify: `src/gen/streets/field.ts` (`shoreTangent` / `shoreTangentNear` / `ShoreGrid`, `boundaryBasis`, `buildBasisFields`, constants)
- Test: `src/gen/streets/field.test.ts`

**Interfaces:**
- Produces: `export interface ShoreProfile { setback(p: Pt): number; off(p: Pt): boolean }`
- Produces: `export function shoreProfile(params: SectorParams): ShoreProfile`. Uses one octave `valueNoise2D` from `../terrain/noise` (already there, range 0..1), sampled at `(p.x / 600, p.y / 600)`. `setback = 30 + 120 × n1`, `off = n2 > SHORE_GAP_ABOVE`.
- Produces: `export function boundaryBasis(terrain: Terrain, profile: ShoreProfile): BasisField` (exported for the test).
- `shoreTangent(terrain, p, maxDist?)` returns `{ angle, dist, course: boolean } | null`. `course` is true when the nearest segment belongs to `riverSlice.course`, the last line `shoreLines` pushes. `ShoreGrid` stores the first course segment index, and the unbounded path compares the winning line with the course.
- Constants: `SHORE_NOISE_M = 600`, `SETBACK_MIN = 30`, `SETBACK_SPAN = 120`, `SHORE_BAND = 150`, `export const SHORE_GAP_ABOVE = 0.6`, `BOUNDARY_REACH = 300` (was 250), `RIVER_REACH = 250`.

Decisions this task pins (the spec leaves them open or contradicts itself):
- Gap threshold 0.6, not 0.7. Value noise is not uniform: over 20 000 samples, one-octave `valueNoise2D` is above 0.7 only 18.5 % of the time (2-octave fractal noise 10.6 %), and above 0.614 30 % of the time. The spec's stated intent ("roughly 30 % of any shore") wins over its number.
- Weight shape: a tent. `dist < s ? dist / s : 1 − (dist − s) / 150`, clamped to 0..1, and 0 where `off`. The spec's formula `1 − |dist − s| / 150` is not 0 at the water line (0.47 for s = 80), which contradicts its own prose "zero at the water". The tent follows the prose.
- Reach 300 m. With a setback up to 150 m, the weight is non-zero up to 300 m from the shore, and a 250 m lookup would cut the band at 250 m.
- Points whose nearest shore line is the river course (in the river, where `riverCrossingSeeds` walk) keep today's weight `1 − dist / RIVER_REACH`. On land, the nearest line is the bank ring, so the profile applies to river banks, coasts and lakes alike.

### Task 2: shore steer and dock ends (arterials)

**Files:**
- Modify: `src/gen/streets/trace.ts` (`TraceOpts`, `MAJOR`, `traceHalf`)
- Test: `src/gen/streets/trace.test.ts`

**Interfaces:**
- Consumes: `shoreTangent(terrain, p, maxDist)` from Task 1 (import from `./field`; no import cycle: field.ts does not import trace.ts).
- Produces: `TraceOpts.shoreLookahead?: number` (undefined = no steer; `MAJOR.shoreLookahead = 60`) and `TraceOpts.deckMax?: number` (declared here, used from Task 3).
- Produces: `export const DOCK_CHANCE = 0.15`, `export const SHORE_MAX_TURN = Math.PI`, `const RIVER_STEER_SLACK = 60`.
- Produces: `function riverAhead(terrain: Terrain, q: Pt, deckMax: number | undefined): boolean`, which is `inRiverBand(terrain, q, RIVER_STEER_SLACK)` in this task (`deckMax` is accepted and ignored). Task 3 adds `&& (deckMax === undefined || riverSpanAt(terrain, q) <= deckMax)`.

The step order inside the `traceHalf` loop decides the behaviour, so it is fixed here:

```ts
const rawDir = rk4Dir(...)
// singularity stop: unchanged, on the FIELD's rawDir (a steered tangent up to 90° off would trip it)
let want = rawDir
if (opts.shoreLookahead && !dock && Math.abs(turned) < SHORE_MAX_TURN) {
  const ahead = { x: p.x + dir.x * opts.shoreLookahead, y: p.y + dir.y * opts.shoreLookahead }
  if (inWater(terrain, ahead) && !riverAhead(terrain, ahead, opts.deckMax)) {
    if (opts.bridgeRivers && !dockDecided) { dockDecided = true; dock = rng.chance(DOCK_CHANCE) }
    const t = dock ? null : shoreTangent(terrain, p, opts.shoreLookahead)
    if (t) want = towards({ x: Math.cos(t.angle), y: Math.sin(t.angle) }, dir)
  }
}
const newDir = clampTurn(dir, want, maxTurn)
if (want !== rawDir) steering = true
// net signed heading change since the first steered step (field turns count too): a coast zigzag stays bounded, a loop does not
if (steering) turned += Math.atan2(dir.x * newDir.y - dir.y * newDir.x, dir.x * newDir.x + dir.y * newDir.y)
```
`dock`, `dockDecided`, `steering` and `turned` are per-half locals. The dock roll happens once per half, at the first non-river water ahead. The spec says both "once per half (`dockDecided` flag)" and "one draw per water approach"; the flag wins. A dock walker walks on with the field direction, and the existing water stop ends it at the bank (the deck rule only bridges a river course, so the sea stops it). Once the heading has turned a net 180° since the first steer (around a peninsula tip or a lake), the steer is off for the rest of the half, and the walker ends at the bank like today. An absolute sum would not work: the field pulls the walker back toward the water after every steered step, and a long coast would use up the budget in a few hundred metres. Everything after `newDir` is unchanged (the river bridge rule, the joins).

### Task 4: river decks cross the highway square (investigation item 7b)

Item 7b (`.superpowers/sdd/2026-10-12-arterials/investigation-streets-seed42.md`, item 7 (b), seed 426750495): two arterial ends at the river stay unbridged because a deck sample comes within `0.3 × sep` = 120 m of the highway, which hugs the far bank (30 m and 93 m away). The clearance exists to keep a deck off another deck or bridge running alongside. A highway the deck crosses square does neither. Rule (both deck paths):

- The highway blocks a deck only on the deck's wet part, and only when (a) the deck crosses a highway segment between two wet samples (deck on deck), or (b) a wet sample lies within the clearance of a highway segment running within 45° of the deck (`DECK_LANDING_ANGLE`, a near-parallel deck). Every other road class keeps today's distance clearance. The dry stretch past the far bank may cross the highway as an ordinary arterial crossing (`highwayCrossings` decks it).

**Files:**
- Modify: `src/gen/sector/bridges.ts` (new helper, `joinRiverStubs` clearance), `src/gen/streets/trace.ts` (in-trace deck clearance in `traceHalf`)
- Test: `src/gen/streets/trace.test.ts`, `src/gen/sector/bridges.test.ts`, `src/gen/sector/generate.test.ts`

**Interfaces:**
- Produces: `export function highwayBlocksDeck(index: RoadIndex, terrain: Terrain, a: Pt, b: Pt, reach: number): boolean` in bridges.ts. It samples a→b every 10 m; only wet samples count. Rule (a) uses `index.segmentCrosses(q0, q1, (_id, c) => c === 'highway')` for each pair of consecutive wet samples. Rule (b) uses `index.nearestMatching(q, reach, (h) => h.cls === 'highway' && angleGapLines(abAngle, h.segAngle) < Math.PI / 4)`. bridges.ts keeps its type-only import of `RoadIndex` (no runtime cycle).
- trace.ts deck loop: the clearance predicate becomes `h.cls !== 'highway' && sameOrHigher(h.cls) && h.id !== onto?.id`, then `blocked ||= highwayBlocksDeck(index, terrain, p, land, 0.3 * sep)`.
